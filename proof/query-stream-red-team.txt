3. Disconnect mid-pipeline
   First attempt (2026-09-25, before the fix): a genuine mid-stream
   disconnect during the pipeline produced a CancelledError traceback in
   SQLAlchemy/asyncpg connection teardown (do_terminate). Root cause:
   worker.cancel() interrupted the DB session's own rollback/close while
   it was mid-await, and -- because the surrounding cancellation kept
   re-arriving at every checkpoint, not just once -- a single
   asyncio.shield()+retry around the cleanup was not enough to let it
   finish either.

   Fix: routers/query.py now enters/exits the session context manager
   manually and runs its __aexit__ (rollback/commit + connection close)
   through _close_session_safely(), which runs cleanup as its own task
   and loops on a shielded await until that task actually reports done,
   only then re-raising the cancellation. Verified locally (outside the
   real stack) that a single retry still lets cleanup get cut off under
   repeated cancellation, while the loop version lets it finish every
   time -- see the two isolated simulations run during development.

   Retest (2026-09-26, after the fix, question: "How does this system
   verify tenant data cannot leak to another tenant?", --max-time 4):
   client received:
     event: stage {"stage": "cache_lookup"}
     event: stage {"stage": "retrieval"}
   then disconnected (curl: (28) Operation timed out, 89 bytes received).
   At the moment of disconnect the worker was mid-retry on a Voyage
   embeddings 429 (rate limit), scheduled to retry after a 25s backoff --
   a realistic, non-trivial cancellation window.
   `docker compose logs app --no-color | grep -E "<trace_id>|CancelledError|
   Traceback|Exception terminating"` over the full container log
   (well past the 25s retry) returned only the original
   voyage.rate_limited line -- no CancelledError, no Traceback, no
   "Exception terminating connection" anywhere in the log.
   Result: PASS

Surprises:

  during testing. Unrelated to this fix; worth adding a payment method
  before further load/latency testing.
- A container restart mid-testing caused a few curl attempts to fail with
  "Connection reset by peer" / 0 bytes received -- not a code issue, just
  bad timing against the restart window.
